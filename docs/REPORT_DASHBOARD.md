# Refreshing the BaSIS report

The report dashboard presents existing Core, Extend and DeepSafe evidence. A
report refresh does not run screening tools, download references, generate
embeddings, infer PathogenFinder2 scores or repeat DeepSafe analyses.

From the BaSIS project directory, run:

```bash
python BaSIS_refresh_report.py -v
```

The default input is `study-isolate1/results-combined/evidence.json`. The helper
validates the bundle schema and the `run`, `samples`, `records` and `deep_records`
containers, then passes those recorded inputs to the installed report renderer.
It creates a new timestamped directory beneath the input directory's
`reporting-reviews` folder. Existing reports and evidence are preserved.

To choose another saved run or a specific new directory:

```bash
python BaSIS_refresh_report.py \
  --evidence study-isolate1/results-combined-validation/evidence.json \
  --outdir study-isolate1/report-review-01 -v
```

An explicitly supplied output directory must not already exist. The helper
refuses to overwrite even an empty directory. It does not change the original
run status, completion time or candidate assessments. Recommendations and other
derived report tables are regenerated by the installed reporting code.

Open the printed `report.html` path. Keep its directory and linked JSON/detail
files together when copying the refreshed report. Selected tree and alignment
artifacts are embedded or copied only after matching their recorded checksums.
Other native artifacts outside the new directory remain in the original run.

The new `review.json` records the source path, its SHA-256 checksum before and
after rendering, the original run identifier, separate report-generation
timestamps, output checksums and the fact that no native analyses ran. Checksums
cover the main artifacts, all files under `report-data/` and the
deferred-candidate TSV. It also fingerprints the installed report renderer
modules so a reporting review can be traced to its presentation code. If the
source checksum changes during rendering, the helper stops without finalizing
the review manifest. A refresh verifies source-file preservation; it does not
independently revalidate every external native artifact referenced by that file.

## Reading the dashboard

- Module execution answers whether the recorded computation completed.
- DeepSafe selected-candidate completion is separate from deferred coverage.
- An unresolved interpretation is not an execution failure.
- PathogenFinder2 scores and attention rankings remain model evidence, not
  organism safety verdicts or functional proof for individual proteins.
- Exploratory source annotations remain exploratory after report generation.

The `-v` option uses `BASIS_VERBOSE=1` for report progress. Report generation is a
CPU/file operation and does not require the Extend GPU environment.

## Linked genome and evidence views (update 23)

The genome explorer uses the saved input validation's protein coordinates,
strands and actual contig lengths. Search for a protein, select an interval on a
track, or use a candidate's **Show genomic neighborhood** button. The overview
and local gene arrows share coordinates; a gene's evidence link opens its
DeepSafe card even if a previous filter hid it. Each sample and contig is kept
separate. The display is linear and does not infer chromosome circularity.

Track colors distinguish evidence sources, not risk. AMRFinder and RGI calls on
the same protein share an interval with both labels retained. Exploratory Loose
matches are excluded from the main screening tracks. Attention nominations are
explicitly exploratory. Missing, failed and completed-empty screens have
different statuses. A genomic-island track remains **not assessed** unless an
actual supported island prediction is supplied; prophages and biosynthetic
regions are never relabeled as islands.

When the original assembly and GFF are available locally and their SHA-256
checksums match the saved run, the report can add GC composition tracks and CDS
product annotations. Otherwise it keeps the recorded coordinate map and states
which optional inputs were unavailable. No input is changed. A displayed gene
product remains an annotation, not experimental proof of function.

The candidate evidence matrix compares selected proteins across screening,
domain/motif layers, comparator availability, taxonomic holds and phylogeny.
Cells are categorical records, not additive evidence votes or confidence
scores. Click a protein to inspect its complete assessment or its neighborhood.

The attention explorer displays recorded nominations and their per-model
attention scores. It does not invent a distribution for all proteins or equate
attention with a pathogenicity probability. Protein feature intervals are
clickable and exportable as SVG.

For completed phylogenetic analyses, existing trees and alignments are shown
only when the explicit native files and expected hashes are available and
match. Missing or changed files yield an availability message; no tree is
reconstructed from a support table and no analyses are rerun. Tree orientation
does not establish a biological root, and split support is not a functional
classification. Query/reference labels retain their recorded provenance.

The browser requires no online scripts, accounts or server. Interactive
controls enhance the static summaries and evidence tables; save the report
folder as a unit when sharing it.

## Citation, motif visibility and optional scope (update 24)

The report credits Jimi Goldstein and provides RIS, BibTeX, CFF and plain-text
software citations. The citation uses the recorded BaSIS version; no DOI,
repository or release date is invented. The underlying tools and databases
still need their own citations. The main `CITATION.cff` is included in the
project, and every generated report contains its own citation downloads.

DeepSafe now begins with a motif/profile coverage table and links to proteins
with recorded custom-rule matches. Each completed candidate shows the recorded
motif name, pattern, matched sequence and amino-acid coordinates, alongside
the distinct PROSITE pattern and profile results. Search terms include motif
sequences and family aliases. A missing custom rule is not a negative scan,
and zero pattern matches do not negate a profile or custom-rule match.

Optional module omissions include their scope, recorded reason and current
integration support. `module_disabled` is shown as disabled in the recorded
configuration. It is not a failed analysis or a negative biological result.
The report does not enable modules or infer whether they are installed.
